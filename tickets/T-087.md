## Summary

Only the `en` dictionary is complete. The `ja/es/fr/ko/zh` dictionaries omit the index hints/descriptions, phase labels, `fc.noCardsDue`, `err.noData`, and `a11y.*`, so they fall back to English. Because `setLocale()` sets `<html lang>` to the chosen locale anyway, screen readers announce English text in the wrong voice.

## Evidence

`t()` falls back to `str = EN[key]`; choosing Spanish still renders "Verbs with sentence patterns" and "Phase 2 (no romaji)".

## Proposed fix

Complete the non-English dictionaries (or drop `data-i18n` on inherently Japanese-only strings) and only set `<html lang>` to a locale whose strings are complete.

## Acceptance criteria

Choosing any supported UI locale translates the full visible chrome; `<html lang>` matches the language actually rendered.
