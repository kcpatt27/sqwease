## Summary

Daily new-card counters use `new Date().toDateString()`, a locale/DST-dependent string, as a stored key.

## Evidence

`const today = new Date().toDateString();` stored and compared; the day boundary and value vary by OS locale and DST.

## Proposed fix

Use a locale-independent key such as `new Date().toISOString().slice(0,10)` (or an integer day index) and migrate stored values.

## Acceptance criteria

Daily reset behaves identically regardless of OS locale; a test with a mocked clock yields the same key.
