## Summary

Replace/augment the simplified SM-2 scheduler with FSRS-6 (DSR model, ~21 weights, desired-retention and maximum-interval controls). Keep SM-2 as a fallback for cards without FSRS state. Do this only after the SRS foundations are fixed.

## Evidence

srs.js is a simplified SM-2; FSRS is the industry-standard successor (Anki 23.10+, ts-fsrs/py-fsrs/fsrs-rs ecosystem). See docs/research/2026-10-09-srs-fsrs-and-upgrade-research.md §3-4.

## Proposed fix

Define a scheduler interface (initCard/reviewCard/isDue/getIntervalDisplay); add fsrs.js as a self-contained port (or a vendored prebuilt ts-fsrs) with a golden-vector parity test generated from py-fsrs/ts-fsrs; run shadow mode, then switch; add per-card review logging for the future optimizer.

## Acceptance criteria

FSRS schedules cards via the interface; parity test passes against a reference implementation; SM-2 fallback works; toggling schedulers does not lose due dates. Blocked by T-009, T-010, T-061, T-085.
