## What's wrong

The dataset branches were cut from an older `main`, so their diff vs current `main` appears to delete the newest tickets (T-102..T-104). A true merge preserves them, but a fast-forward or a confused reviewer could regress the tracker.

## Evidence

merge-base main lang/ko-2500 = 311fa7b while main = 455e223; `git diff --name-status main..lang/ko-2500 -- tickets` shows `D tickets/T-102.md` / `D tickets/T-103.md` / `D tickets/T-104.md`. Session-audit ledger rows 1-2.

## Minimal fix

Either rebase each `lang/*-2500` branch onto `main` before merging, or record explicitly that these branches merge (not fast-forward) so the older tracker state does not win.

## Acceptance criteria

Merging a dataset branch does not remove any ticket.
