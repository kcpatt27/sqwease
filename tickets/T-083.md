## Summary

In dark mode the kana table header row becomes a light strip because its
background is `var(--secondary-text)`, which is a light gray in the dark theme
while the text is dark.

## Evidence

Dark-mode scan: `TH` background `rgb(199,205,212)` (≈ dark `--secondary-text`)
with dark text `rgb(45,52,54)` (≈ dark `--card-bg`). Readable, but jarring and
inconsistent with the dark surface.

## Proposed fix

- Use a surface token for the header background (`var(--border)` or a dedicated
  `--table-header-bg`) that reads correctly in both themes.

## Acceptance criteria

- Kana table headers look consistent in both themes and the header text meets
  4.5:1.
