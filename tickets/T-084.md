## Summary

When a target language has no Boxes/Kana/Kanji/Editor, the menu card is visually
disabled but (a) still carries an `href`, so assistive tech/programmatic
activation can navigate to an unavailable page; (b) the whole card is dimmed to
55% opacity, including the only explanatory note; and (c) the note interpolates
the English `active.name`, so it reads e.g. "Todavía no disponible para
Japanese." in a Spanish UI.

## Evidence

- `.menu a.is-disabled { pointer-events: none; }` (index.html:91) and
  `syncCapabilities()` sets `aria-disabled`/`tabindex="-1"` but never removes the
  `href` (index.html ~210-220).
- The `.note` spans are hardcoded English text nodes updated to
  `t('common.notAvailable', { lang: active.name })` (index.html:220).

## Proposed fix

- Remove `href` (keep it in a data attribute) while disabled and restore it when
  re-enabled.
- Style the `.note` with `var(--muted)` instead of dimming the whole card.
- Pass a localized target-language display name (add per-locale names to
  `SqweaseLangs`/`i18n`).

## Acceptance criteria

- Disabled cards cannot navigate by mouse, keyboard, or assistive tech.
- Disabled cards keep readable text and a fully localized "not available" note.
- Re-enabling the language restores the link.
