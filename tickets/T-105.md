## What's wrong

The French and Chinese branches commit their generator (`content/fr/enrich.py`, `content/zh/enrich_source.py`); Korean and Spanish do not. Korean's README describes a "small deterministic Revised-Romanization script" used for 1,548 romanizations, but that script is not in the repo, so `source.tsv` cannot be regenerated or the romanization verified.

## Evidence

git ls-tree -r --name-only lang/ko-2500 -- content/ko → README.md, source.tsv only; lang/es-2500 → README.md, source.tsv only; lang/fr-2500 → enrich.py; lang/zh-2500 → enrich_source.py. Session-audit ledger 2026-10-09-korean rows 3-5,10.

## Minimal fix

Commit the pipeline used (download + filter + gloss + romanization) as `content/ko/enrich.py` (and `content/es/enrich.py`), matching fr/zh, so `source.tsv` is reproducible and the derived RR is auditable.

## Acceptance criteria

Re-running the committed script reproduces `source.tsv` byte-for-byte on the same sources.
