## Summary

The token editor is wider than the viewport below ~430 px. The 7-column
`.token-table` has a large min-content width and no horizontal-scroll wrapper, so
it stretches `.container` (and the page) beyond the screen.

## Evidence

Measured via a same-origin iframe at 320 px wide:

- `documentElement.scrollWidth` = 391 vs `clientWidth` = 305.
- `.container` min-content = 478 px, driven by `.token-table` (140 px max-width
  inputs + 80 px particle column × rows). `.toolbar` already wraps
  (editor.html:60), so the table is the cause.

## Proposed fix

- Wrap `.token-table` in a `div` with `overflow-x: auto` (as `kana-charts.html`
  does with `.chart-wrap`), or give the table `display: block; overflow-x: auto`.

## Acceptance criteria

- No page-level horizontal overflow on `editor.html` at 320/375 px; the table
  scrolls within its own container.
- The editor still passes the a11y audit (table headers/labels).
