## Summary

The project has **no test framework and essentially no automated tests**: only
`romaji-test.js` / `run-romaji-test.js` (7 duplicated kana cases) and the shell
gate `scripts/check.js`. There is no `package.json`, no `test/`, no CI. Several
shipped defects (coloring drift, SRS interval overflow, CSV corruption, unchecked
language decks) had no failing test to catch them.

Test strategy decided in **ADR-011** (`DECISIONS.md`): Node's built-in
`node --test` + `node:assert/strict`, zero third-party dependencies, wired into
the existing gate.

## Plan (from ADR-011)

1. **Runner.** Add `test/` with `*.test.js` files; `node scripts/check.js` runs
   `node --test test/` first, then the existing checks. Keep `node
   scripts/check.js` as the one gate; no `package.json`.
2. **Suites (one file each):**
   - `test/romaji.test.js` — extend the shared case list (T-023) and cover the
     edge cases from T-015: orphan `ー`, `ヴ`/`ゔ`, small-katakana combos
     (`ティ`/`ファ`/`ウィ`/`シェ`), combining dakuten, sokuon-before-vowel, ん +
     full-size ヤ; plus particle detection (T-016) and `shouldColorToken`.
   - `test/srs.test.js` — state transitions, `getIntervalDisplay`, and the
     caps/date math from T-009/T-010 (assert no `RangeError` after N Easy
     ratings; ISO day keys).
   - `test/coloring.test.js` — `syllable-color.js` / `boxes-coloring.js` with a
     minimal `document` stub: `shouldColor` decisions, no empty colored spans,
     the fixed alignment fixtures from T-005/T-006, and palette contrast
     invariants (T-034).
   - `test/build-lang-vocab.test.js` — run the builder on a small fixture TSV →
     assert id formatting, dedupe, symbol filtering, and deterministic output.
   - `test/decks.test.js` — every `data/<lang>/vocab.js` has ≥1 word, unique
     `w`/ids, strictly increasing ranks, and matches its `content/<code>/source.tsv`
     row count (this is T-106).
3. **Determinism probe.** Each data/build test rebuilds and asserts the output
   is unchanged (byte-level where feasible).

## Acceptance criteria

- `node scripts/check.js` runs the unit suite and fails if any test fails.
- Each suite above exists with the listed cases; a deliberately broken module
  (e.g. remove the SRS interval cap) makes the gate fail.
- No new runtime dependency, no `package.json`, `file://` support unchanged.
- CI (`.github/workflows/ci.yml`, if added later) runs only `node scripts/check.js`.
